The portfolio is a **Next.js 16** application deployed on Vercel. It uses the App Router with server components for data fetching, a flat JSON content layer for all static copy, and Supabase for dynamic data (blogs, likes, skill progress, and contact submissions). The rendering model is deliberately simple: every page is a React Server Component that fetches what it needs at request time, then hands a fully-typed `content` prop down to the client shell.

## Data flow

Every section of the portfolio traces back through one of two paths: the static JSON content layer for copy and structure, or a live Supabase query for dynamic data (blogs, skill progress, likes). Both paths converge in `app/page.tsx`, which runs the fetches in parallel, then passes the results into `HomePageLoaderShell`.

```text title="Static content path"
content-data/*.json
  └── lib/content.ts  (imports all JSON, assembles portfolioContent)
        └── app/page.tsx  (imports portfolioContent, passes as prop)
              └── components/home-page-loader-shell  (renders sections)
```

```text title="Dynamic data path"
Supabase (blogs table / portfolio_skill_progress)
  └── lib/blogs.ts + lib/skill-radar.ts  (server-side fetch)
        └── app/page.tsx  (Promise.all, passes latestPosts + skillCategories)
              └── components/home-page-loader-shell  (renders sections)
```

```ts title="app/page.tsx — parallel fetch"
export const dynamic = "force-dynamic";

export default async function HomePage() {
  const [latestPosts, skillCategories] = await Promise.all([
    getLatestBlogs(4),
    getSkillShowcaseCategories(),
  ]);

  return (
    <HomePageLoaderShell
      content={portfolioContent}
      latestPosts={latestPosts}
      skillCategories={skillCategories}
    />
  );
}
```

### API routes

All server endpoints live under `app/api/`. They handle contact form delivery (Nodemailer + Web3Forms), blog like toggling (Supabase), and the AI assistant proxy (OpenRouter).

## Root layout

`app/layout.tsx` is the single root layout. It loads the three-font trio, exports Next.js `Metadata` assembled from `content-data/site-metadata.json`, and appends analytics scripts after the page is interactive.

```ts title="app/layout.tsx — font stack"
const geist = Geist({ subsets: ["latin"], variable: "--font-sans" });

const inter = Inter({
  subsets: ["latin"],
  variable: "--font-body-source",
  display: "swap",
});

const instrumentSerif = Instrument_Serif({
  subsets: ["latin"],
  weight: "400",
  style: "italic",
  variable: "--font-display-source",
  display: "swap",
});
```

Three analytics layers run in the layout: **Umami** (privacy-friendly, loaded via `next/script` with `afterInteractive`), **Vercel Analytics** (page views), and **Vercel Speed Insights** (Core Web Vitals).

<Note>
  `trailingSlash: true` is set globally. All internal links must include the trailing slash, or Next.js will issue a redirect.
</Note>
